## 已知宿主及协议边界

固定 Paseo [`0.17.4` 源码（`2b3559b1`）](https://github.com/getpaseo/paseo/tree/2b3559b107243306986176b80beb0e779f9fe53e) 核查只用于解释宿主契约，没有与本机运行二进制逐项比较，也没有执行 askuser 原生验收。不得据此标记下列体验通过。

- **已输入文字的全选填文本 Dismiss**：宿主将它与 Submit 编码为相同的非空 allow，公开协议没有动作标识，插件无法区分。全空 allow 已保护为本地收起；全空用例不能证明所有 Dismiss 都零写入。
- **条件错误**：拒绝提交会保留原生表单，宿主内联显示通用“回答失败”错误，不能展示 provider 抛出的具体原因；题目与时间线提供具体条件提示。真实输入保留与视觉效果待测。
- **首次发现与通知**：初次打开至 `session.ready` 期间权限按历史静默恢复；ready 后新权限走 live 路径。首次后台发现后主动打开也可能静默，首次未打开 Thread 的注意力通知尚未证明。宿主系统通知标题固定为 `Agent needs permission`，卡片 title／description 用于可读正文；是否通知还取决于焦点、在线客户端和推送设置。详见 [主动加载与通知边界](askuser-wakeup.md)。
- **跳过真实协议**：尚无真实 `askuser-skip` HTTP 状态／返回体、已跳过 timeline JSON 或专用 WebSocket 事件样本。模拟成功响应不依赖正文，使用已有前端契约建模的 `askuser_skipped_at`／`askuser_skipped_by` 核对；202 仅在 timeline 确认后完成，其他成功响应缺少元数据时不补造远端时间或操作者。失败后不自动重发，需核对远端结果。
- **权限身份**：稳定 ID 精确为 `multica:askuser:<cardCommentId>:<attachmentId>`，按 provider session、连接与 Issue 地址隔离；不能通过给 ID 添加账号前缀改变已确认契约。

## 用户手动部署与验收（全部待执行）

使用当前 `0.17.4` daemon，无需另设 `0.15.x` 实机验收；manifest 仍保持 `>=0.15.3`。以下操作会真实读写受控测试 Issue，应在用户手动更新已安装源码后执行。本轮未替用户运行这些步骤。

1. **记录并部署**：记录源码提交、归档 SHA-256、daemon 版本、插件安装源目录、当前 CLI 服务／用户／Multica 工作区、测试 Issue、Thread 根与卡片评论 ID，以及起始评论数。按 [README 安装说明](../README.md#构建与安装) 校验并更新已配置源目录、安装生产依赖、reload `multica`。先保存该目录的本地改动与未跟踪文件，备份 daemon 插件状态和占位目录，等相关 Run／投递结束后再 reload。相同插件 ID 不重复安装；reload 会释放已加载 provider 会话，不能用保持 daemon PID 证明讨论未受影响。部署后核对原 agent ID、历史和隐藏状态。
2. **根／子回复与主动加载**：准备带标题、长警示及指定答复者的根卡片和子回复卡片，先不打开所属 Thread。同步后检查仅符合条件的讨论被加载、侧栏 `needs_input` 与原生表单可见；已运行讨论的 Run、聚合活动和其他 tab 不受中断。无卡片、已收起、人工隐藏和已归档讨论保持原状态。检查时间线可读取完整警示、问题与选项。
3. **原生通知和重放**：在目标讨论未聚焦、推送条件满足时，分别记录“首次未打开讨论发现”和“ready 后新卡片”的真实表现，正文应有可读卡片标题／说明而非 JSON。重启或重新加载后已有待答卡片恢复，历史不重复通知。记录焦点、客户端在线与通知配置，若首次发现静默则如实保留该限制。
4. **填写、校验与提交**：覆盖必填／选填／多行文本、单选、多选、含逗号标签、other、触发及不触发的 `required_when`，尤其前置单选选 other。缺失条件文本时检查表单保留与通用内联错误，再修正提交。核对网页识别为已答、实际正文逐字符合 `**确认结果**` 格式、恰好一条评论，保存状态与 Run 状态分开。对子卡片检查 `parent_id`、`askuser_answer_to` 同为卡片评论 ID。通过网页提交超过 200 runes 的完整回答，确认下一次同步消除待答，无摘要截断误判；另核对 `answer_user_id` 与 `delegated_by`。
5. **Dismiss 与重展**：普通表单 Dismiss、全空选填文本表单 Dismiss 分别记录零评论 POST／零 skip POST、原生权限消失而远端仍待答；重启／同步后保持本地收起，点“重新展开作答”恢复表单及待答状态，包括宿主释放空闲会话后。已输入文字的全选填表单存在上述宿主歧义，单独记录结果，勿用此操作处理真实重要卡片或声称普遍零写入。
6. **两步跳过与协议采样**：先取消确认，验证零 skip POST；再确认跳过并记录真实 `POST /api/issues/{issue_id}/comments/{card_comment_id}/askuser-skip` 的 HTTP 状态、Content-Type 与脱敏正文结构（含空正文）。随后保存完整 `GET /api/issues/{issue_id}/timeline` 中对应记录的脱敏结构，核对 `askuser_skipped_at`、`askuser_skipped_by` 的存在性、类型和值，并观察是否存在专用 WebSocket 已答／已跳过事件。检查网页和插件终态、权限消除与时间／操作者显示；不要将本地操作时间写作远端时间。实际协议如有差异，先修正实现与公开边界回归，再将该项标为通过。
7. **投递核实与 Stop**：在受控网络条件下验证回答保存后响应丢失进入待核实，原生重复提交入口消失；核实原回执和明确重发均保留子目标且无盲目重复。核对目标服务的真实幂等支持，7 天边界的自动化模拟不称为实际等待 7 天。验证 Stop 只取消当时归属 Run，不远端跳过卡片；等待身份或工作区核实的旧回答／跳过／重发不再发出，之后可显式重展；普通聊天不触发卡片提交。
8. **只读和身份保护**：使用受控权限测试非指定用户、Issue 删除／失权、筛选退出、Paseo 工作区归档、人工隐藏、离线、CLI 登出／切换服务或账号及同账号 Token 轮换。核对旧权限清除、无跨身份附件／回答／skip 请求、隐藏不被自动撤销；已读卡片、终态和警示在管理页只读历史跨重启可读。离线不是已答／已跳过证据，恢复后核对远端状态。

每项记录执行时间、构建身份、期望／实际结果、对应的脱敏请求与 UI 证据；凭据不进入截图、日志或仓库。实际未执行、宿主限制和失败分别保留，不以模拟结果补齐勾选。用户完成后再更新本记录及 #26；本轮未关闭任何真实验收项。
