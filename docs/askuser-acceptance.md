## 模拟验证范围与已知宿主边界

测试入口位于 [tests/askuser.test.ts](../tests/askuser.test.ts)、[tests/askuser-wakeup.test.ts](../tests/askuser-wakeup.test.ts) 与 [tests/bundle.test.ts](../tests/bundle.test.ts)，使用临时 CLI 配置、受控时钟、隔离 HTTP/WebSocket、原生宿主替身及 `paseo-esbuild` 编译后的客户端 bundle 验证以下契约（未运行真实 Electron/Web 宿主渲染与系统通知）：

| 验证维度 | 模拟边界已验证行为 |
| --- | --- |
| 附件缓存与安全边界 | 根评论与子回复卡片归属正确 Thread；按连接 / Issue / 附件 ID 持久缓存，严格限制当前 API 同源、禁止重定向、流式上限 64 KiB 与 schema `version: "1"`；异常仅在卡片报错，不阻断普通评论。 |
| 终态核对与轮询收敛 | 存在未决卡片的 Issue 额外拉取完整 `timeline`，准确识别超过摘要 200 runes 截断的回答、转义 Markdown、`answer_user_id`、`delegated_by` 与条件必填；确认已答/已跳过终态后停止额外拉取。 |
| 原生表单映射与答案格式 | 稳定权限 ID `multica:askuser:<cardCommentId>:<attachmentId>`（按会话、连接与 Issue 隔离）；覆盖文本、单选、多选、含逗号标签、`other` 与 `required_when`；提交生成精确中文 `**确认结果**` 评论，`parent_id` 与 `askuser_answer_to` 均指向卡片评论，同 key 在网络/`5xx` 下最多尝试 3 次。 |
| 全选填文本防误提与本地收起 | Paseo `0.17.4` 原本会将全选填文本表单已填文字时的 Dismiss 编码为 `allow`。插件仅为全选填文本表单追加一题「提交确认」：点击 Dismiss 走 `deny`、缺少确认或原题全空均只本地收起（零远端请求）；跨同步与重启保留收起状态，点击「重新展开作答」可唤醒已释放会话。含必填或选项题的表单不追加确认题。 |
| 两步远端跳过 | 编译客户端须二次确认，取消确认零请求；成功不依赖响应 JSON 正文，尽力从 `timeline` 读取 `askuser_skipped_at` / `askuser_skipped_by`（无远端元数据时不伪造本地时间或操作者，`202 Accepted` 无 `timeline` 终态证据不标完成）。Stop 仅本地收起待答表单，不远端跳过。 |
| 后台主动唤醒与通知时序 | 仅对启用规则内、未归档、未人工隐藏、无 `hold` 且当前用户可答未收起的待决卡片调用无中断 `listCommands(agentId)`（60 秒去重限流，不中断活跃 Run）；本进程首次发现的新卡片等待 `listCommands` 注册完成后再 live 公布，重启缓存仍在 `ready` 前静默回放（详见 [当前规格](./spec.md#askuser-结构化提问与后台唤醒) 与 [设计依据](./design.md#paseo-宿主与插件契约)）。 |
| 身份隔离与离线只读 | 切换身份或登出立即清理旧连接待决权限并拒绝跨连接回答/跳过；同账号 Token 轮换保留缓存与本地收起状态；已读卡片与终态跨离线、登出与重启保持只读可见，远端 `403`/`404` 直接返回错误。 |

**待实机确认的宿主与协议细节**：

- **条件必填错误展示**：provider 拒绝提交会保留原生表单，但 Paseo `0.17.4` 内联仅显示通用失败文案，具体缺失条件需结合题目说明与时间线卡片提示确认实际视觉效果。
- **系统通知触发条件**：宿主系统通知标题固定为 `Agent needs permission`，卡片标题与说明进入正文；实际是否弹出还受窗口焦点、在线客户端与系统推送开关影响。
- **远端 `askuser-skip` 真实响应样本**：尚未采集真实服务端 `POST .../askuser-skip` 的状态码、返回体、已跳过 `timeline` 字段及是否存在专用 WebSocket 事件。

## 用户手动部署与验收清单（待执行）

在目标 `0.17.4` daemon 与受控测试 Issue 上按顺序执行并记录脱敏证据（切勿将凭据写入日志或截图）：

1. **备份与热重载部署**
   - 记录源码提交、产物 SHA-256、daemon 版本、当前 CLI 服务/账号与测试 Issue 起始评论数。
   - 备份 daemon 插件状态目录，待在途 Run 与评论发送结束后，按 [README 安装说明](../README.md#3-构建安装与更新) 更新固定安装目录、运行 `npm ci --omit=dev --ignore-scripts` 并执行 `paseo plugin reload multica`，核对既有讨论 ID、历史与人工隐藏未受破坏。
2. **未打开讨论的后台唤醒与运行保护**
   - 在受控 Issue 准备带标题、长警示及指定答复者的根评论卡片与子回复卡片，先保持所属 Thread 未打开。
   - 等待后台同步后，确认侧边栏对应讨论出现 `needs_input` 提醒、打开可见原生表单与完整时间线警示；同任务其他运行中 Run 不被中断，已人工隐藏或已归档的讨论不被唤醒。
3. **原生通知与重启静默回放**
   - 在目标讨论未聚焦且开启系统通知时，观察首次发现新卡片与已打开会话收到新卡片时的通知正文（应显示可读卡片标题/说明而非原始 JSON）。
   - 重启 daemon 或 reload 插件后，确认已有待答表单自动恢复且不会重复弹出历史通知。
4. **表单填写、条件校验与答案提交**
   - 依次测试必填/选填/多行文本、单选、多选、含逗号选项、`other` 以及触发/不触发的 `required_when`（含前置单选选 `other`）。故意留空必填条件验证表单保留，修正后提交。
   - 在 Multica 网页核对卡片变为已答、评论正文逐字符合 `**确认结果**` 格式且仅生成 1 条评论（子卡片回答的 `parent_id` 与 `askuser_answer_to` 均为卡片评论 ID）。另从网页提交一条超过 200 字符的长回答，确认下次同步准确消除待答。
5. **本地 Dismiss 收起、全选填确认题与重新展开**
   - 对普通表单及全选填文本表单（空白、已填文字、已填文字并勾选「提交确认」）分别点击原生 **Dismiss**，验证零评论 POST / 零 skip POST、本地表单收起而远端仍为待答；确认全选填表单勾选确认后点击 **Submit** 仅保存原题正文（不含确认题），含必填或选项题的表单不出现确认题。
   - 同步及 reload 后确认仍保持收起；点击时间线卡片 **重新展开作答** 确认原生表单恢复（含空闲会话释放后的重开）。
6. **两步远端跳过与真实协议采样**
   - 点击 **跳过此卡** 后先取消，确认零请求；再次点击并 **确认远端跳过**，采集脱敏后的 `POST /api/issues/{issue_id}/comments/{card_comment_id}/askuser-skip` 状态码与响应结构，以及 `GET /api/issues/{issue_id}/timeline` 中 `askuser_skipped_at`、`askuser_skipped_by` 的实际字段和 WebSocket 事件表现。若真实协议与模型存在差异，先更新实现与测试。
7. **发送失败提示与原生 Stop 边界**
   - 在受控断网或错误条件下提交回答，确认报错后原生表单或重试入口可用、网络恢复后可重新提交（注意先核对远端是否已落库）。
   - 在存在活跃 Run 与待答卡片的讨论点击原生 **Stop**，确认仅取消当时归属该讨论的活跃 Run 且本地收起表单，远端卡片未被跳过，重新展开后仍可正常提交回答；确认底部普通聊天框发送普通评论不会误当作卡片回答。
8. **权限边界、离线缓存与身份隔离**
   - 验证非指定答复者、任务退出筛选归档、人工隐藏、离线及 CLI 登出/切换账号场景：旧连接待决表单立即清除，无跨身份下载/回答/跳过请求；在原生归档历史与离线状态下，已缓存卡片内容、完整警示与终态仍保持只读可见，强行向已无权限目标写入时直接报告远端 `403`/`404` 错误。
