# 按服务与用户身份隔离本地映射

评论的 user/assistant 角色取决于连接用户，而原生历史消息不能任意改写角色，因此更换身份时复用同一历史会产生错误的作者语义。
更换 Multica 服务或账号时使用独立的本地映射，旧历史保留原连接身份；同一服务与账号只更新 Token 时继续使用原映射。
连接状态、CLI profile 与筛选由插件管理页集中管理，daemon 侧只读复用 CLI 管理的凭据，见 [ADR 0008](./0008-reuse-multica-cli-authentication.md)；隐藏状态随各自连接身份保留，恢复旧连接继续遵循其原有隐藏意愿。

#13 以标准化 API 服务地址与 `/api/me` 返回的真实用户 ID 组成连接键，凭据值和 profile 名称不参与历史身份。原子替换、同账号重新登录或选择同账号 profile 后仍使用原 project／workspace／tab；新服务或用户从独立空规则开始。原生评论首次投影角色、Run owner、人工隐藏、停止 epoch／告警和投递意图始终保存在原连接内，切回原身份不重建映射。

已解析的 daemon 请求上下文带有仅在内存中存在的撤销 signal 和 `assertCurrent`。每个远端读取在发送及读取响应后重新核对当前 profile 与有效 CLI 服务／凭据对；评论分页、输出明细、目录和停止请求共用此边界。检测移除或变更后撤销原上下文、关闭旧认证 WebSocket；重连与 auth 发送前也重新读取 CLI，不借用缓存凭据。已经发送的请求不能因登出而撤回；其响应不作为新身份的权威数据，原输入或停止告警继续保留。新评论的最终核对必须位于原 Stop 栅栏之前，随后保持立即发送，避免为了检查身份引入停止后的投递空隙。

`connection.history` 只读本地已验证的服务、用户、曾用 profile 和保留对象数量，登出后仍可用；凭据不持久化。当前来源与当前身份继续通过 `connection.status` 显示。规则管理列表携带连接键，管理页的目录、启用和规则保存操作携带所展示的原连接键；CLI 在点击前换账号时拒绝旧操作，不把同名工作区的规则写入新身份。早期无身份摘要的历史映射保持可读，不猜测用户。

公开贡献入口的实际 loopback HTTP／WebSocket 测试覆盖同账号轮换与 profile 切换、不同账号／服务的相同远端对象 ID、旧原生角色与 Run owner、人工隐藏、待核实输入、取消告警、登出和切回原映射；在 `/api/workspaces` 等待时登出或切换账号不会再发送旧评论或取消请求。真实宿主与目标服务演示由母工单另行记录；没有独立插件 Token、浏览器登录或刷新令牌流程。

## 修订：减少重复验证（OPT-13）

共享远端请求只在发送前核对一次有效 CLI 服务、凭据和 profile，删除响应后的重复读取；评论仍在持久领取前核对，旧连接不能借用新登录发送。CLI 配置按文件 mtime 与大小缓存解析，`/api/me` 验证结果在内存中保留最多 60 秒，配置变化或远端 401／403 使其失效；凭据不持久化。
