# 保留原生评论消息并追加更正记录

现有外部 provider 接口不支持任意替换或删除原生 user/assistant 历史消息，因此不能同时保留原生消息语义并承诺远端编辑、删除原位反映到这些记录。
首版选择原生消息：远端评论编辑时追加更正内容，删除时追加删除提示，保留原消息，而不将所有评论改为可替换的插件卡片。
状态变化与更正、删除提示作为独立事件呈现，不冒充新的参与者发言；首版对远端评论的编辑与删除仍在 Multica 完成。

Paseo 0.15.3 实际导入时，notification 映射未保留 provider 稳定 ID，首次重放会暂时重复任务描述，因此描述改用稳定 ID 的 `task-description` 插件行及 Markdown renderer，参与者消息仍只来自评论。插件行只带有界预览，全文按需分页读取，并以已有连接映射与描述版本避免跨版本拼接；缓存读取依靠宿主鉴权，CLI 离线、退出登录或切换 profile 时仍可读取旧连接缓存。恢复已有历史遵守 `history: skip`，既有原生通知保持原样。

#5 将首次读取的原生消息与后续观测状态分别持久化。原生 `user_message`／`assistant_message` 不原位更新；编辑和删除使用稳定插件行 ID，重复事件、重复读取与正常会话重放复用同一记录。首次读取前已经发生的编辑没有可恢复的旧版本，不追加虚构的更正。删除根的 tombstone 只形成删除记录及仍可访问的回复，不虚构原始文本。

后台分页读取概要，不将裁剪后的正文导入原生消息。Paseo 导入本身会打开 provider 会话，因此 Thread 概要插件行在实际渲染时经 `thread.open` 请求完整历史；缓存通过 provider replay 重放，新记录通过会话订阅追加。评论最近活动分页与单 Thread 回复分页使用各自的组合游标，不能以默认评论列表的上限替代完整历史。只有完整成功且未声明截断的快照可以据缺失推断删除。

每条原生评论紧邻一条稳定的“评论来源”插件记录，显示首次读取快照中的原始发言时间与来源更新时间；缺少时间则明确说明不可用。独立系统／更正／删除行也保存并显示来源时间，provider 时间线事件携带可用的有效来源时间。当前核查的宿主在历史重放路径读取该时间，在实时追加路径仍以本地时间入库，因此原生消息时间可能为本地导入时间，不能宣称始终等于来源时间。超过插件行大小预算的事件只在行内放摘要，完整已读文本通过只读 `thread.event` 提供。


#14 的恢复不能把本地 rows/observed 或相邻来源插件行当成原生参与者消息的提交回执。新 provider 会话的 `history:skip` 订阅先通过公开 `fetchAgentTimeline` 完整分页读回所属 native agent，按保留的来源 `messageId`、角色与首次原文核对；实际 0.15.3 即使请求 canonical 也返回 projected，仍保留所需来源 ID，因此兼容此响应。只有全部旧页成功、epoch 稳定且无 gap/stale/reset 后，才发布缺失的缓存原文。重复核对用本次会话的投影去重集合，更正／删除／来源插件行继续按稳定 ID 更新；不持久保存“已提交”捷径，后续进程重启仍重新读回。来源记录不一致或分页失败时保留缓存并报告核对未完成，不用无差别 replay 重复原生消息。

任务描述另外通过只读 `description.observe` 观测缓存并刷新同一插件行；renderer 挂载后立即及定期观察，不依赖历史 replay。已读全文依然按版本分片，过期版本不会混接新正文。恢复不会自动下载所有曾读过的 Thread／Run 正文；原文缓存与原生缺失核对独立于本次展开的远端增量读取。

#10 的自身评论还保存原输入 clientMessageId。宿主会把提供此 ID 的 user_message 对应到同一原生乐观输入，公开 canonical 记录可能以 clientMessageId 作为 item.messageId，来源 commentId 则在宿主内部单独关联。因此缓存原文核对还接受相同 clientMessageId 的同角色／全文精确匹配，不能只依赖来源 ID。主讨论的新输入与其新建 Thread 根分属不同 native agent；新 Thread 导入不复用主讨论的 clientMessageId。插件接收但尚未取得回执的输入从独立 deliveries 恢复，不能伪装成远端已保存评论。

真实 0.15.3 重启验收发现，同一已保存回复可同时存在于 Thread 评论缓存与 durable delivery 中。provider replay 与 `history:skip` 缺失恢复因此共用本次 native 会话的原文身份集合，以角色／commentId 与自身输入 clientMessageId 关联两种表示；已经核对存在的评论原文也进入该集合。来源插件行仍独立投影，但同一轮不再分别追加评论原文与投递原输入。集合随会话关闭释放，不跨主讨论或新 Thread 去重，也不按相同正文推断未知回执；失败、待核实与仅本地保存的缺失输入仍逐条恢复。正常实时输入后的精确回执 echo 继续携带原 clientMessageId，供宿主关联其乐观输入。

## 修订：精简时间线（OPT-01）

不再为每条原生评论追加独立来源卡；来源时间仍保存在缓存和 provider 事件中，更正、删除及系统事件继续显示已有来源时间。Thread 挂载仍读取历史，仅在读取或同步失败时显示提示；主讨论保留触发历史读取的隐藏条目，不再显示冗余的任务事件头卡。成功投递仅在主讨论提示新 Thread 已建立，可从侧边栏打开。

## 修订：评论回声关联（OPT-06）

删除 durable delivery 原输入重放和恢复路径。成功投递只保存 clientMessageId、commentId 与讨论归属；Thread 缓存原文仍携带 clientMessageId，与来源 commentId 共用会话原文去重集合。同步在在途 POST 完成后关联回声，失败输入不另行持久化或重放。

## 修订：依靠原生归档历史（OPT-08）

删除独立只读快照浏览器与失权二次取证。完整筛选列表中消失的任务统一按筛选退出归档，原生历史及已读缓存保留；远端写入遇到 403／404 直接报告错误，不再由本地访问状态拦截。

AskUser 卡片同样移除只读快照集成与 inaccessible 二次取证；完整卡片继续由原生时间线和 AskUser 缓存读取，403／404 直接报告远端错误，指定答复者、卡片终态与隐藏／归档保护保留。

## 修订：由 provider 推送描述（OPT-04）

删除讨论内同步状态轮询和任务描述观测轮询；描述更新由 provider 的现有订阅推送同一稳定条目。Thread 挂载仍读取历史，仅显示读取失败及重试入口。

## 修订：恢复即时输入投影

本地校验通过后，在 prompt_result 之前直接发出携带 clientMessageId 和原正文的原生 user_message，保留已验收的宿主输入行为。远端失败时原生输入保留，随后追加一条错误；插件仍不持久化失败投递或在重启后另行恢复它。
