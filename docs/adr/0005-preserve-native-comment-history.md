# 保留原生评论消息并追加更正记录

现有外部 provider 接口不支持任意替换或删除原生 user/assistant 历史消息，因此不能同时保留原生消息语义并承诺远端编辑、删除原位反映到这些记录。
首版选择原生消息：远端评论编辑时追加更正内容，删除时追加删除提示，保留原消息，而不将所有评论改为可替换的插件卡片。
状态变化与更正、删除提示作为独立事件呈现，不冒充新的参与者发言；首版对远端评论的编辑与删除仍在 Multica 完成。

#5 将首次读取的原生消息与后续观测状态分别持久化。原生 `user_message`／`assistant_message` 不原位更新；编辑和删除使用稳定插件行 ID，重复事件、重复读取与正常会话重放复用同一记录。首次读取前已经发生的编辑没有可恢复的旧版本，不追加虚构的更正。删除根的 tombstone 只形成删除记录及仍可访问的回复，不虚构原始文本。

后台分页读取概要，不将裁剪后的正文导入原生消息。Paseo 导入本身会打开 provider 会话，因此 Thread 概要插件行在实际渲染时经 `thread.open` 请求完整历史；缓存通过 provider replay 重放，新记录通过会话订阅追加。评论最近活动分页与单 Thread 回复分页使用各自的组合游标，不能以默认评论列表的上限替代完整历史。只有完整成功且未声明截断的快照可以据缺失推断删除。

独立系统／更正／删除行保存来源时间；Paseo 当前原生消息接口不能指定来源时间，因此原生消息的时间是本地导入时间。超过插件行大小预算的事件只在行内放摘要，完整已读文本通过只读 `thread.event` 提供。
