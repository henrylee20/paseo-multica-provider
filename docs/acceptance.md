## 交付环境与构建核验

- **宿主与清单**：manifest 声明 `requirements.paseo = ">=0.15.3"`，不改 Paseo 核心。锁定开发依赖为 `@getpaseo/plugin`、`client`、`protocol` `0.15.4`。实机验收先后覆盖 `0.15.3` 独立 daemon、`0.17.4` 独立 daemon 与用户主 `0.17.4` daemon（`paseo plugin reload multica` 热重载验证）。
- **真实云基线**：`https://api.multica.ai`（仅操作授权测试任务 `HENR-1` / `HENR-2`），复用运行用户默认 Multica CLI `0.6.3`（提交 `18fa9f728`）登录态。
- **产物与离线加载检查**：独立 worktree 执行 `npm ci --ignore-scripts && npm run check && npm run build` 生成源码安装目录、`.tar.gz` 与 `.sha256`（不含 `node_modules`、Git 元数据或本地运行状态）。将压缩包解压至独立目录执行 `npm ci --omit=dev --ignore-scripts` 后：
  - 使用实际 `0.17.4` 宿主编译器编译双端入口，并以 `0.17.4` 与 `0.15.3` SDK 验证加载（`0.17.4` 注册 `multica-mention`，`0.15.3` 自动跳过）；
  - 安装至全新隔离 `0.17.4` daemon home，在合成任务隔离环境下验证状态正确报告 `missing_config`、零越权读取拥有者 CLI，验证后完整清理隔离进程。

## 实机验收发现并已闭环的关键宿主问题

1. **恢复已活跃工作区报错与 `idPrefix` 未过滤（`0.15.3`）**：宿主拒绝对活跃 workspace 调用 `restoreWorkspace`，且 `fetchWorkspaces` 不按 `idPrefix` 过滤；实现改为完整分页比对工作区 ID，已活跃时直接跳过恢复。
2. **早期活动丢失与复用已完成 turn ID 卡死（`0.15.3`）**：`session.ready` 前发出的活动不被导入记录接收，且复用已结束 turn ID 会使完成事件被宿主忽略；实现改为打开后发布活动，并为每次新活动周期及 Stop 后剩余活跃 Run 分配全新 UUID。
3. **恢复工作区 60 秒时间戳回退唤醒隐藏讨论（`0.17.4`）**：无论是筛选重返还是设置页「恢复 Paseo 工作区」，当子记录缺少精确归档时间戳匹配时宿主都会回退唤醒同工作区隐藏讨论；实现通过 `restoreWorkspacePreservingHidden` 在恢复前后持有 `hold`、结束本地活动投影并重新归档未选中解除隐藏的讨论。
4. **跨 Paseo 版本升级时的 worker 协议不匹配（`0.15.3 → 0.17.4`）**：旧 daemon 进程加载新版本插件文件会触发协议拒绝；重启目标 daemon 统一进程与安装文件版本后恢复正常。
