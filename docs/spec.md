# Paseo–Multica 首版规格

状态：27 项产品决定及自部署、CLI 登录复用补充已获整体确认；已发布 [规格 issue #1](https://github.com/henrylee20/paseo-multica-provider/issues/1)，作为实现与任务跟踪依据。尚未实现或完成运行验收。
已发布正文的本地副本见 [github-spec.md](./github-spec.md)。
决定来源与接口证据见 [设计访谈](./design.md)，术语见 [GLOSSARY](../GLOSSARY.md)，工程步骤见 [实现计划](./implementation-plan.md)。

## 目标与接入方式

将 Multica 作为 Paseo 的远端 agent provider，让符合筛选规则的任务出现在原生左侧项目树中，并在 Paseo 查看讨论、发送评论、观察和停止执行。

首版不修改 Paseo 核心。插件由 provider、daemon 侧同步器和客户端界面组成；同步器维护原生 project/workspace/agent 记录及其本地占位目录。占位目录不是 Multica 的代码工作区，原生文件与终端功能可能指向它们。

## 对象映射

| Multica 对象 | Paseo 表达 |
| --- | --- |
| 工作区 | Project |
| Issue（业务任务） | Workspace |
| Issue 内的顶层评论及其全部后代回复（Thread） | 一个 agent tab |
| 当前连接用户的普通评论 | 原生 user message |
| 其他成员或 agent 的普通评论 | 带作者名前缀的原生 assistant message |
| 一次 Run | 所属 tab 中可展开的执行段 |
| 状态变化、评论更正、评论删除等系统记录 | 独立事件 |

此外，每个 Issue 有一个本地“主讨论”tab，展示 Issue 描述和首次确定归属时没有评论关联的 Run。它自身不是一个远端 Thread。

一条 Thread 可以先后或同时产生多个 Run；一个 Run 也可能处理多个 Thread 的评论。Paseo 中的展示归属与这些远端关联关系分开记录。

## 连接与身份

- 支持云服务与自部署 Multica。默认直接复用本地 Multica CLI 的登录上下文，不要求另填服务地址或生成新的 Token；例如 CLI 已登录 selfhost.xxx.com，就使用该上下文对应的 API 地址和现有凭据。
- 每个连接绑定一个 Multica 服务和一个用户身份。插件管理页展示登录来源与连接状态、选择 CLI profile 并管理筛选；凭据继续由 CLI 管理，插件只在 daemon 侧读取，不复制到插件配置或客户端。
- “自己”以当前连接用户的身份 ID 判定。自己拥有的 agent 仍是 agent 作者，不能当作本人的 user message。
- 换服务或换账号采用独立本地映射，旧历史保留原身份与消息角色；同一服务、同一账号更新 Token 续用原映射。
- 本地 project、workspace、tab、Run 归属和人工隐藏状态具有持久身份，正常重启、重连与归档恢复不能重复创建它们。

### CLI 登录发现与更新

- 默认与不带 `--profile` 的 CLI 使用同一 profile；CLI 没有全局“当前 profile”选择器，使用命名 profile 登录时需在插件中显式选择同一 profile。
- 以 CLI 的实际配置解析规则为依据，保留 `MULTICA_SERVER_URL`、`MULTICA_TOKEN` 等有效环境覆盖及任务隔离边界。API 地址 `server_url` 与前端地址 `app_url` 分别使用，不假定二者相同。
- CLI 重新登录、登出或原子替换配置后重新读取上下文。有效凭据被移除时停止继续使用旧凭据；同账号凭据更新不重建项目，服务或账号变化不把旧投递转发到新身份。
- 已核查 CLI 的浏览器登录流程保存已有 PAT，未提供刷新令牌机制。失效后引导用户通过 CLI 重新登录；插件不自行发起浏览器登录、生成新 PAT 或改写 CLI 配置。
- 复用的是 **Paseo daemon 所在主机、运行用户可访问的 CLI 登录态**。客户端位于另一台机器或 daemon 使用另一用户时，不能自动借用客户端或其他用户的凭据。
- 复用登录不自动启用任务筛选：空规则仍不导入任务。

具体依据与兼容性边界见 [ADR 0008](./adr/0008-reuse-multica-cli-authentication.md) 和 [设计证据](./design.md)。

## 任务筛选与可见性

用户显式启用工作区与规则；空配置不导入任何任务。
每个 Multica 工作区按负责人（成员、agent、squad）、状态、标签和 Multica project 筛选：不同字段取交集，同字段多个值取并集；多个标签表示命中任一标签。
新规则默认只纳入未开始和进行中的任务，其他字段不限。“直接分配给我”与“分配给我的 agent/squad”不能混为同一个条件。

| 变化 | 本地行为 |
| --- | --- |
| 任务开始匹配 | 创建或恢复对应 workspace 与 tab |
| 任务不再匹配 | 自动归档，保留身份与历史，不取消远端执行 |
| 任务重新匹配 | 自动恢复，人工隐藏的对象除外 |
| 用户关闭 tab 或归档 workspace | 持久记录人工隐藏，直到用户主动恢复 |
| Issue 删除或失去访问权限 | 移出活跃列表、禁止写入，保留只读历史 |
| 网络故障或连接级 Token 失效 | 标记连接异常，不把所有任务当作删除或退出筛选 |

恢复访问后重新核对远端状态，继续尊重人工隐藏。隐藏与归档是同一 Paseo daemon 各客户端共享的状态。

## 评论与发送

真实 Thread tab 的普通发送回复该 Thread 的根评论。主讨论每次发送创建 Issue 下的一条新顶层评论及新 Thread，后续在对应 Thread tab 继续回复。

普通发送使用 Multica 原有 agent 路由。允许显式 agent mention；成功保存评论不保证启动 Run。运行中默认仍提交普通评论，由 Multica 排队或合并，不额外要求注入当前 Run；用户主动选择 Paseo 的中断或排队发送模式时，遵循对应原生行为。

首版发送文本，读取文本、Markdown 和已有附件链接。上传附件、编辑和删除评论、新建 Issue、修改任务状态均在 Multica 完成。

原生消息保留初次导入的内容。远端评论编辑时追加更正内容，删除时追加删除提示；这些通知与系统状态变化不冒充参与者的新发言。原消息不会被原位清除。
首次导入以远端可获取的快照为准，不承诺恢复从未读取且远端不再提供的早期版本。

## 投递结果与重试

“输入已被插件接收”“评论已保存”“智能体已开始执行”是不同结果，不能互相代替。

同一次投递固定请求编号、正文与目标。短暂故障后先查询是否已经发表；只有已验证服务提供去重保证，且仍在有效期内，才自动重试。
超过保证期限、服务不支持或结果仍无法确认时保持“待核实”，由用户核实后决定重发。不能把未查到过期回执当作从未发表，也不能把投递失败或结果不明显示为发送成功。

服务端评论回显必须与 Paseo 的发送记录关联，避免同一条评论出现两次；幂等回执只证明评论保存，不证明执行已触发。

## Run 的唯一展示归属

首次确定归属时依次选择：

1. 触发评论所在的 Thread。
2. 没有触发评论时，最早关联评论所在的 Thread。
3. 没有评论关联时，该 Issue 的本地主讨论。

一旦确定就持久保留。来自其他 Thread 的后续合并或追加评论只更新关联信息，不迁移或复制执行段；最初放在主讨论的 Run 也不例外。
网络错误不能被当作“没有关联评论”，从而过早固定错误归属。

每个执行段展示 agent、状态、逐条工具调用及结果、运行文本和错误。最终评论作为正常对话消息出现，运行日志不另复制为主对话回复。
若远端已截断输出或缺少可靠工具配对字段，明确展示现有信息与缺失情况，不补造内容或调用关系。

## 原生停止与关闭

| 操作 | 远端行为 |
| --- | --- |
| 原生停止 | 取消此次操作时归属当前 tab 的全部未结束 Run，包括等待执行的 Run |
| 关闭运行中的普通 agent tab | 允许先请求上述取消，再归档 tab |
| 归档整个 workspace | 仅改变本地展示，不取消远端 Run |
| 筛选退出导致自动归档 | 不取消远端 Run |
| 客户端断开、空闲资源释放或单纯连接关闭 | 不取消远端 Run |

停止范围不包括其他 tab 的 Run，也不修改历史上已结束的 Run。跨 Thread 的一个 Run 只能整体取消，不能只取消其中部分讨论。

多个 Run 部分取消失败时逐项显示真实结果，原生停止报告失败。即使原生关闭继续完成归档，管理页仍保留未停止 Run 的告警和重试入口，不自动重开 tab，不宣称全部停止。
服务器已接受取消、任务已标为取消和远端进程已经清理完成也要区分；仅有 HTTP 成功不足以声称进程已退出。

## 后台同步与历史

客户端连接时自动引导 daemon 侧同步，无需专门打开插件页。启动成功后，关闭客户端仍可继续同步；daemon 或插件进程重启后需要至少一次客户端连接重新引导。首版不承诺完全无人连接时恢复。

后台同步匹配任务、Thread 和 Run 的概要。打开 tab 时读取评论历史，展开执行段时加载工具输出，不人为限制为最近若干条。
断网保留已读取内容并标记同步状态。重连后重新核对任务范围与数据快照，补读执行流，重复事件不能产生重复记录。

## 管理界面与工程约定

以下是为已确认行为安排的界面与工程细节，不增加业务范围，可在实现验证中调整：

- 管理页集中呈现 CLI 登录来源、实际服务地址、连接状态、profile 选择、筛选规则、人工隐藏对象、不可访问历史、投递问题及取消失败；恢复对象与重试操作不要求用户重新创建映射。
- 项目使用 Multica 工作区名称；workspace 使用任务编号（若有）与标题；Thread tab 使用根评论摘要，本地主讨论固定标识为“主讨论”。名称不充当身份。
- 创建 Thread 后在该任务下提供对应 tab；后台同步不抢夺用户当前浏览位置。
- mention 必须编码为 Multica 能识别的身份引用；选择或复制入口优先使用公开插件扩展点。不能把任意同名文本默认为已确定的接收者。
- 首次历史回放按源时间组织，并保留来源时间；晚到补录与更正清楚标识，不能伪装成新的参与者发言。
- 远端执行输出中的路径按远端信息展示，不把它们当作占位目录中的本地文件。

## 实施验证与交付条件

现有 0.15.3 安装包静态核查已包含所需能力，参考 SDK 为 0.15.4，尚无必须升级的证据。实际运行 daemon 的版本与插件加载兼容性仍需验证。
Multica 的真实连接也需要验证 CLI 登录上下文、身份、读取权限及幂等接口能力；公开源码支持某功能不等于用户实例必然支持。已完成本地 CLI 配置发现规则及凭据存在性的只读检查，尚未据此调用用户服务或验证登录有效性。

实现必须通过 [验收场景](./design.md#已确认决策的验收场景尚未执行)，重点验证：角色与回显、唯一 Run 归属、按 tab 停止、归档与断线不误取消、人工隐藏、幂等重试、部分失败、断线恢复与版本兼容。
当前仅完成设计与静态接口核查，尚无功能代码、运行测试或端到端验收结果。
