# Paseo–Multica 设计依据

本文件集中记录 Paseo 宿主与 Multica CLI / 服务端的**固定版本源码核查事实**，解释插件架构与边界背后的上游约束。插件当前行为以 [当前规格](./spec.md) 与 [ADR 目录](./adr/README.md) 为准，模块职责与不变量见 [AGENTS.md](../AGENTS.md)，实际运行验证范围见 [交付验收记录](./acceptance.md)。

## 核查基线

- **Paseo 基线**：初次静态核查的桌面客户端与随附包为 `0.15.3`，锁定开发 SDK 为 `0.15.4`（提交 [`1c00b365`](https://github.com/getpaseo/paseo/tree/1c00b365c9e0b74c1580eba33d905d693125ae21)，其中 `plugin/dist` 31 个、`protocol/dist` 77 个、`client/dist` 23 个 JS 文件与本机 `0.15.3` 逐字节一致）；后续实机与复核覆盖 `0.17.4`（提交 [`2b3559b1`](https://github.com/getpaseo/paseo/tree/2b3559b107243306986176b80beb0e779f9fe53e)）。
- **Multica 基线**：服务端与核心类型核查提交 [`33215cec`](https://github.com/multica-ai/multica/tree/33215cec572fd2a9859c702311dfb23b80bc8be5)；Multica CLI 为 `0.6.3`（提交 [`18fa9f72`](https://github.com/multica-ai/multica/tree/18fa9f728a9e25f2465df2789631edb2a75442ad)）。

## 已核查的上游约束

### Paseo 宿主与插件契约

- **项目/工作区同步与目录要求**：外部 provider 契约不提供原生 project / workspace 的枚举与创建，需由插件同步器另行维护；交互式 workspace 与 agent 要求 daemon 主机上存在真实目录，非 Git 目录可用。[Provider 契约](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/plugin/src/server/provider.ts#L29)、[Workspace source](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/protocol/src/messages.ts#L2715)。
- **后台引导生命周期**：公开插件服务端 `contribute` 不提供 daemon 启动 hook 或高层 `PaseoApi`；客户端贡献可通过 RPC 引导后台同步，启动后客户端断开仍继续运行，但客户端 `setup` 不会在每次重连时重新执行，且 daemon 重启后至少需要一次客户端连接触发幂等引导。[服务端上下文](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/plugin/src/server/contracts.ts#L30)、[客户端 RPC](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/plugin/src/client/contracts.ts#L294)、[连接生命周期](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/docs/plugins.md#L624)。
- **中断与本地关闭的区分**：原生 Stop 与关闭运行中的 root-agent tab 都发送不带原因字段的 `session.interrupt`（`0.15.3` 与 `0.15.4` 相同），provider 无法区分；运行中刷新/替换/回退也可能先触发中断，若假应答成功而不停止远端，宿主会强制将 turn 结算为 `canceled`。[中断调用](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/lifecycle-command.ts#L96)、[拒绝与结算](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/agent-manager.ts#L3351)。相反，整 workspace 归档、空闲释放及 daemon 关闭直接走 `session.close` 而不发中断；`deleteAgent`（已在 `0.15.3`、`0.17.4` 与 `main` 核实）以及 `archiveWorkspace`、`removeProject`（已在 `0.17.4` daemon 源码核实）均仅调用 `closeAgentRuntime` 发送 `session.close()`，不会误取消远端 Run。宿主无物理删除工作区记录的公开接口，已归档工作区记录保留在注册表中。[workspace 归档](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/workspace-archive-service.ts#L517)。
- **工作区与讨论恢复边界**：归档是 daemon 级共享状态。保留占位目录并分别恢复 workspace 与已归档 agent 可保持原身份（`resumeAgent(handle)` 会分配新身份，`import` 活跃 handle 也不是 upsert）；`refreshAgent` 对运行中的存活 agent 会先中断再重载，仅可用于已确认归档的恢复场景；底层 create / restore / import / refresh 位于 `@getpaseo/client/internal/daemon-client`。[Workspace 恢复](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/session/workspace-recovery/workspace-recovery-service.ts#L103)、[Agent 恢复与运行中 refresh](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/session.ts#L4760)。此外，`0.17.4` 恢复归档工作区时若无精确时间戳匹配的子记录，会按 60 秒窗口回退唤醒其他已归档子讨论，需由插件在恢复前后加锁保护并重归档人工隐藏项。
- **单一活动 turn 与只读子会话**：Paseo 每个 tab 只有一个活动 turn 槽位，多个并行或排队远端 Run 必须由 provider 聚合维护；同时宿主 UI 不使单纯的 `sub_agent` 工具徽章可点击展开详情，而带 `paseo.parent-agent-id` 的独立子 agent 又会暴露输入框和独立 Stop。因此插件使用 `session.subsession` 将每个 Run 投影为内存态只读 provider subagent，并在父时间线保留静态 `sub_agent` 位置标记（[ADR 0011](./adr/0011-run-as-provider-subagent.md)）。[单一 turn 映射](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/plugin-provider.ts#L1524)。
- **发送模式与客户端队列**：公开 provider 的 `ProviderPrompt.delivery` 仅有 `auto | steer`（内部 `tryHandleOutOfBand` 不对外部插件开放）。若 `steer` 返回 `failed` 等非匹配当前 turn ID 的结果，外部适配器会将其视为不可用并触发中断替换；显式 `interrupt` 在宿主确认取消成功后才发出 `auto` prompt。显式 `queue` 保存在客户端，待该 tab 转为空闲时以 SDK `activeTurnBehavior: steer` 释放队首（避免恰好开始的新 turn 被中断）；队列「立即发送」复用普通 composer 路径并遵循当前发送模式。[公开 prompt 契约](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/plugin/src/server/provider.ts#L132)、[外部适配器](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/plugin-provider.ts#L1293)、[composer 队列](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/app/src/composer/actions.ts#L246)、[队列释放](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/app/src/runtime/host-runtime.ts#L2563)、[手动立即发送](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/app/src/composer/index.tsx#L1949)。
- **时间线消息身份与重放去重**：原生 `user` / `assistant` 消息不支持按稳定 ID 原位修改或物理删除（同 ID `assistant` 用于流式追加，`user` 更新会生成新消息）；仅工具调用与 `timeline.plugin` 条目支持稳定身份替换，且插件条目单行上限为 64 KiB、无删除 API。Timeline transformer 只接收 `item` 与 `phase`，拿不到行级 `providerMessageId`，且渲染变换不更新持久化内容。`0.17.4` 复核还确认普通消息的 item ID 去重仅保存在单次 provider 会话内存中，跨重启 `history:skip` 仍须完整分页读回核对。[消息映射](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/plugin-provider.ts#L1895)、[身份规则](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/protocol/src/timeline-identity.ts#L3)、[插件 timeline 契约](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/docs/plugins.md#L639)、[Transformer 契约](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/plugin/src/client/contracts.ts#L261)、[消息回显协调](https://github.com/getpaseo/paseo/blob/1c00b365c9e0b74c1580eba33d905d693125ae21/packages/server/src/server/agent/agent-manager.ts#L5079)。
- **设置、提及选择器与提问表单契约**：`PluginSettings` 服务端仅提供 `read` 与 `subscribe`，无服务端写设置接口，因此 profile 切换清理须基于持久归属对账（`0.15.3` 与 `0.17.4` 客户端均提供 `SettingsSelect`）。输入框 `@` 候选固定为工作区文件，插件提及选择器依赖 `0.16` 新增的 `addComposerItem` / `useComposer` / `Combobox` 与 `setMetadata`（[ADR 0009](./adr/0009-composer-mention-picker.md)）。`0.17.4` 的 `QuestionFormCard` 对全选填文本表单会将已填内容的 Dismiss 编码为 `allow`，且拒绝提交时只内联显示通用错误；初次打开会话时早于原生 manager 注册完成的 `session.permission` 按静默历史处理，只有等待无中断 `listCommands(agentId)` 返回后发出的新权限才走 live 注意力路径（操作系统通知标题固定为 `Agent needs permission`，卡片标题与说明进入通知正文）。

### Multica 服务与 CLI 契约

- **Run 与评论结构**：API 的 `AgentTask` / `task_id` 代表单次运行，可合并同一 Issue 下不同 Thread 的评论，也可无触发评论直接运行；同一 agent 在单 Issue 内串行执行，不同 agent 可并行，可取消的活动状态为 `queued`、`dispatched`、`running`、`waiting_local_directory`、`deferred`。评论作者分成员、`agent`、`system`，执行消息分 `text`、`thinking`、`tool_use`、`tool_result`、`error`。[运行字段](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/packages/core/types/agent.ts#L316)、[跨 Thread 合并](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/agent.go#L807)、[评论字段](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/packages/core/types/comment.ts#L1)、[执行消息](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/packages/core/types/events.ts#L364)、[执行串行范围](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/pkg/db/queries/agent.sql#L822)、[取消状态](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/pkg/db/queries/agent.sql#L1525)。
- **筛选、提及、幂等与取消接口**：标准分页 Issue 列表支持全部筛选维度，而 `open_only=true` 走旧分支会忽略标签等条件；agent 提及要求 `[@名称](mention://agent/<id>)` 链接，回复根评论不保证触发执行；评论发送支持最长 255 字节的 `Idempotency-Key`（服务端幂等指纹含 Issue、`parent` 与 `type` 但不含正文，故同 key 重试必须固定正文与目标）；单任务取消接口返回最新记录，HTTP `200` 可能是竞态中自然完成的终态，且状态广播不等待远端进程物理退出。[列表分支](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/issue.go#L1459)、[mention 解析](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/util/mention.go#L19)、[评论路由](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment.go#L2723)、[幂等实现](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment_idempotency.go#L21)、[取消接口](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/chat.go#L1918)、[取消服务](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/service/task.go#L3108)。
- **CLI `0.6.3` 配置与隔离**：默认与命名 profile 位于 `<配置根>/config.json` 与 `<配置根>/profiles/<name>/config.json`（`MULTICA_TASK_CONFIG_ROOT` 覆盖根目录，无 XDG、无 profile 列表命令、无全局 active profile）；`auth logout` 仅清空 `token` 并以 `0600` 原子重写文件；浏览器登录换取 90 天 PAT 落盘，无刷新令牌或浏览器 Cookie 共享；任务上下文检测禁止借用拥有者全局凭据；API 地址与 `app_url` 分开解析。[配置发现](https://github.com/multica-ai/multica/blob/18fa9f728a9e25f2465df2789631edb2a75442ad/server/internal/cli/config.go#L228)、[profile 解析](https://github.com/multica-ai/multica/blob/18fa9f728a9e25f2465df2789631edb2a75442ad/server/cmd/multica/cmd_agent.go#L252)、[地址解析](https://github.com/multica-ai/multica/blob/18fa9f728a9e25f2465df2789631edb2a75442ad/server/cmd/multica/cmd_agent.go#L296)、[任务隔离](https://github.com/multica-ai/multica/blob/18fa9f728a9e25f2465df2789631edb2a75442ad/server/cmd/multica/cmd_agent.go#L377)、[登录流程](https://github.com/multica-ai/multica/blob/18fa9f728a9e25f2465df2789631edb2a75442ad/server/cmd/multica/cmd_auth.go#L308)、[原子写配置](https://github.com/multica-ai/multica/blob/18fa9f728a9e25f2465df2789631edb2a75442ad/server/internal/cli/config.go#L310)。

## 评论附件接口核查（Issue #41）

- **Paseo 输入与能力**：`0.15.4`（`1c00b365`）与 `0.17.4`（`2b3559b1`）契约一致：透传普通 text、base64 image、uploaded_file 及 forge/github/text/review 特殊附件。图片不按 provider 能力降级，SDK 要求 `prompt.image`。普通文件的 path 为 daemon 本机 `PASEO_HOME/uploads/<id>/<净化文件名>`，app 单件上限 50 MiB，完成上传不再进入超时清理；插件作为同用户子进程可读取。以下行号按 `0.17.4`：[内容与能力](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/plugin/src/server/provider.ts#L779)、[输入框拆分](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/app/src/composer/attachments/submit.ts#L48)、[文件限额](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/app/src/composer/actions.ts#L131)、[上传路径](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/server/src/server/file-upload/index.ts#L52)、[完成上传](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/server/src/server/file-upload/index.ts#L188)、[插件子进程](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/server/src/server/plugins/runtime.ts#L305)。
- **宿主回显**：实时输入保存附件药丸，持久原生消息仅保存 prompt 文本块；provider 的 `user_message` 按 `clientMessageId` 对账，因此跨客户端及重载需要独立持久插件行。插件保留原有主讨论行 ID 与版本 1 `{}`，扩展可选附件数据。[发送药丸](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/app/src/composer/actions.ts#L205)、[持久文本](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/server/src/server/agent/agent-manager.ts#L5915)、[回显协调](https://github.com/getpaseo/paseo/blob/2b3559b107243306986176b80beb0e779f9fe53e/packages/server/src/server/agent/agent-manager.ts#L5951)。
- **Multica 上传（`33215cec`）**：`POST /api/upload-file` multipart 必需 file，可选 issue_id，须 `X-Workspace-Slug` 才创建附件记录；上限 100 MiB，超限 413。上传无幂等，数据库写入失败仍可能返回 200 和空 id，插件必须拒绝，不能自动重传。[上传与工作区](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file.go#L397)、[Issue 校验](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file.go#L491)、[空 ID](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file.go#L657)、[100 MiB](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file_upload_limits.go#L5)。
- **评论关联与幂等**：空 content 即使带附件也拒绝；attachment_ids 为 UUID，同工作区、当前 Issue 或同上传者未绑定草稿且未绑定评论才可关联，否则 409、事务回滚。重放在守卫之后、附件锁之前，返回含附件的原评论；指纹不含正文和附件 ID，必须固定 K、正文、目标及 ID 全集。当前插件未发送 `steer_task_ids`，不依赖附件分支的定向 steer 行为。[空正文](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment.go#L1691)、[重放顺序](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment.go#L1853)、[锁与 409](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment.go#L1904)、[指纹](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment_idempotency.go#L69)、[含附件重放](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/comment_idempotency.go#L145)、[绑定条件](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/pkg/db/queries/attachment.sql#L96)。
- **附件持久链接**：`download_url` 可能是短期签名，不应持久化；`markdown_url` 契约为持久链接。插件优先保存该字段，缺失时使用稳定 `/api/attachments/<id>/download`；私有附件仍需浏览器登录，不向客户端转交 CLI 凭据。其他评论的既有附件展示与指纹不变。[字段契约](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file.go#L79)、[持久地址生成](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file.go#L253)、[下载工作区解析](https://github.com/multica-ai/multica/blob/33215cec572fd2a9859c702311dfb23b80bc8be5/server/internal/handler/file.go#L970)。
